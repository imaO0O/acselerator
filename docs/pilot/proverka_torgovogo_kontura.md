# Проверка торгового подбора в контуре предприятия

## Что проверено в проекте

Автоматический тест `tests/test_trade_offline.py` запрещает вызовы HTTP-клиента и создание сетевых соединений через `socket.create_connection`. С этими ограничениями он импортирует три вымышленных каталога, подбирает позиции, читает текст PDF и открывает сформированные Excel и Word. Разбор письма GigaChat, LDAP и сетевые выгрузки в этот тест не входят.

## Проверка на стенде заказчика

1. Запустите агента и локальные серверы моделей. Отключите доступ в интернет на стенде средствами предприятия, сохранив доступ к разрешённым адресам локальных служб. Зафиксируйте, какие адреса разрешены для LDAPS или файлового сервера, если они используются.
2. Пройдите сценарий от загрузки прайса и заявки до выгрузки Excel и КП. Отдельно проверьте чат с GigaChat, распознавание скана, вход через LDAPS и синхронизацию выгрузки, если эти функции включены.
3. Во время прогона соберите отчёт сокетов для процессов веб-интерфейса, API, моделей и фоновых задач. Укажите каждый отдельно запущенный PID в параметре `--pid`.

   ```powershell
   python scripts/check_connections.py --pid 1234 --pid 5678 --include-children > network-snapshot.json
   ```

4. Сопоставьте сетевой журнал за весь прогон с разрешёнными адресами. В акте запишите дату, версию, проверенные сценарии и решение службы безопасности. Снимок сокетов показывает состояние в момент проверки. Поле `complete: false` означает, что сбор неполон. Для вывода обо всём прогоне требуется также журнал сетевых правил или захват трафика со стороны ИТ-службы.

## Подключения для пилота

- В разделе «Подбор товаров → Каталоги и прайсы» сопоставьте колонки и, при наличии регулярной выгрузки, укажите её полный путь на сервере. Проверьте кнопку «Обновить выгрузки сейчас». Для запуска каждые 15 минут на Windows используйте `scripts/install_trade_task.ps1`. Задача работает в сеансе пользователя, от имени которого её зарегистрировали. Для круглосуточной установки ИТ настраивает отдельную учётную запись запуска.
- Для входа через AD или LDAP соберите поставку с `--with-ldap`. Укажите `KB_AUTH_PROVIDER=ldap` и `KB_LDAP_CONFIG=<путь к JSON>` в настройках установки. В JSON задайте `host`, `ca_file`, `base_dn`, `bind_dn`, `bind_password_file` и `group_roles`. Поле `group_roles` связывает полные DN групп со штатными ролями агента. В LDAP без атрибутов AD укажите имена `username_attribute`, `display_attribute` и `group_attribute`. Работают прямые членства в группах. Сеанс требует повторного входа через пять минут. Перед переключением подтвердите вход пользователя и администратора на тестовой копии.
- Чтобы включить AES-256-GCM для существующего RAG-индекса, подготовьте отдельный файл ключа из 32 случайных байт и выполните `python scripts/encrypt_index.py --index-dir data/index --key-file <путь к ключу>`. В настройках службы задайте `KB_INDEX_KEY_FILE` с этим же путём. Проверьте чтение индекса с ключом и отказ запуска поиска без него.

## Обновление с носителя

Скопируйте пакет в новую папку рядом со старой установкой. До запуска установщика проверьте пакет доверенной копией `scripts/verify_bundle.py`.

```powershell
python scripts/verify_bundle.py --root D:\agent_bundle
```

Проверка SHA-256 выявляет пропуски, подмену файлов относительно списка и лишние файлы. Происхождение самого списка проверьте по каналу поставки. После успешной проверки запустите `install.bat` из новой папки и выполните перенос данных из новой установленной копии.

```powershell
.\.venv\Scripts\python.exe scripts\update.py --from D:\agent_old
```

В резервную копию входят торговый каталог, оригиналы источников и журнал пилота. Для зашифрованного RAG-индекса перенесите доступ службы к отдельно хранимому ключу `KB_INDEX_KEY_FILE`. Шифрование этого индекса не покрывает торговую SQLite и файлы прайсов. Допуск пользователей, резервные копии и защиту диска определяет ИТ-служба.
