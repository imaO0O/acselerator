# Техническое описание для ИТ-службы и службы безопасности предприятия

Коротко: AI-агент отвечает сотрудникам по внутренним документам и учётной базе со ссылкой на документ, пункт
и страницу. Всё — языковая модель, поиск, документы, журналы — работает на сервере предприятия, интернет
не нужен ни для установки, ни для работы.

## Из чего состоит

| Компонент | Что делает | Где слушает |
|---|---|---|
| Языковая модель GigaChat 3.1 Lightning (открытая, MIT, 10 млрд параметров, q4) через llama.cpp | составляет ответ только из найденных фрагментов, переводит вопрос по учёту в SQL | 127.0.0.1:8080 |
| bge-m3 (векторы) и bge-reranker-v2-m3 (оценка релевантности) через llama.cpp | поиск по смыслу и отбор фрагментов | 127.0.0.1:8081, 8082 |
| Чат (Streamlit) | рабочее место сотрудника и страница администратора | порт 8501, доступен из сети предприятия (ограничить адрес — `server.address` в `.streamlit/config.toml`) |
| REST API (FastAPI) | тот же агент для портала, 1С, чат-бота внутри сети | порт 8000, доступ по ключу |
| Индекс | разобранные документы: пункты, страницы, векторы | `data/index` (12 МБ на 2 000 фрагментов) |
| Журналы | вопросы и ответы; действия (входы, загрузки, ключи) | `logs/audit.jsonl`, `logs/actions.jsonl` |

Модели вызываются по OpenAI-совместимому интерфейсу: вместо llama.cpp можно подключить сервер моделей
предприятия, если он уже есть.

## Сколько нужно оборудования

Замеры — `eval/results/load.md`, `eval/results/laptop.md`, `eval/results/smallgpu.md`, `eval/results/scale.md`.

| Масштаб | Оборудование | Время ответа (медиана) | Пропускная способность |
|---|---|---|---|
| Проба, демонстрация | компьютер без видеокарты NVIDIA, 16 ГБ памяти | около минуты | только чтобы посмотреть работу системы |
| Пилот, отдел до 30–50 сотрудников | ноутбук или ПК с видеокартой NVIDIA от 4 ГБ, 16 ГБ памяти | 8,4 с на ноутбуке RTX 3050 4 ГБ | около 7 ответов в минуту (по времени ответа, один вопрос за раз) |
| Предприятие, 600–1000 активных сотрудников | сервер с одной видеокартой 12 ГБ (класс RTX 5070) | 1,2 с; при 8 одновременных вопросах — 5–9 с | 50–80 ответов в минуту (замер) |
| Больше 1000 сотрудников | сервер с видеокартой 24–48 ГБ или двумя видеокартами — несколько копий модели | — | кратно числу копий (оценка) |

Расчёт: активный сотрудник задаёт 3–5 вопросов в час. Число документов на время ответа почти не влияет:
на 100 000 фрагментах (около тысячи документов) поиск занимает 14–19 мс, векторы — 391 МБ памяти.
Диск: 12 ГБ (модели — 7,3 ГБ) плюс сами документы.

## Безопасность

- **Закрытый контур.** Проверено: браузер загружает ресурсы только с сервера чата, процессы чата и моделей
  держат соединения только с 127.0.0.1, сбор статистики Streamlit отключён. Установка — без интернета,
  из папки поставки с контрольной суммой SHA-256 каждого файла (`scripts/make_bundle.py`).
- **Вход и права.** Пароли — PBKDF2-SHA256 (200 000 итераций), сеанс — 12 часов; не короче 10 символов, буквы и цифры. Пользователей заводит администратор («Пользователи»): временный пароль меняется при первом входе, блокировка и сброс пароля завершают сеансы сразу, последнего администратора не удалить; при установке `scripts\first_run.py` удаляет демо-учётки. Документы разделены на группы
  доступа по ролям: сотрудник не получает ответа из документа, закрытого для его роли (проверка —
  `eval/roles.yaml`, 6 из 6).
- **Учётная база — только чтение.** Подключение `mode=ro` + `PRAGMA query_only`, разрешён один оператор SELECT;
  просьбы изменить или удалить записи агент отклоняет.
- **Защита от подмены инструкций.** Текст документов для модели — данные, а не указания; вставки вида
  «игнорируй инструкции» вырезаются из вопроса. Ответ без подтверждённой ссылки на документ не показывается.
- **Журналы.** Вопросы и ответы — для поиска ошибок и пробелов в документах; действия — входы, неудачные попытки
  входа, загрузка, утверждение и удаление документов, выдача ключей API, запросы с неверным ключом.
  Видит только администратор.
- **Персональные данные (152-ФЗ).** Перед записью в журнал вопросов и в оценки маскируются телефоны, почта,
  паспорт, СНИЛС, ИНН человека и ФИО полностью — то, что сотрудник может вписать в вопрос (рабочие сведения
  вроде «ответственный — Белов И. Н.» остаются). Журнал вопросов хранится 180 дней (`KB_LOG_RETENTION_DAYS`),
  журнал действий — пока его не очистит служба безопасности.
- **Ключи API** хранятся только в виде хэша SHA-256, у каждого ключа своя роль.
- **Серверы моделей — только с ключом доступа.** Ключ создаётся при первом запуске `start_servers` в
  `data/model_api_key.txt` (в поставку не входит) и передаётся серверам файлом, поэтому в списке процессов
  его не видно; запрос без ключа получает 401. Новый ключ — удалить файл и перезапустить серверы.

## Установка и сопровождение

1. На компьютере с интернетом: `python scripts\make_bundle.py E:\agent_bundle` — папка поставки около 9 ГБ.
2. На сервере предприятия: `install.bat` (Python, окружение, пакеты — из папки поставки; сборка llama.cpp —
   под видеокарту NVIDIA или процессор), затем `start_servers.bat` и `run_chat.bat`.
3. Проверка: `python scripts\check_demo.py` — «ГОТОВО К ПОКАЗУ».
4. Документы предприятия загружаются на странице «Администрирование» (PDF, DOCX, сканы); новая редакция
   отменяет прежнюю, агент показывает, что изменилось.
5. Резервная копия — `python scripts\backup.py create` (или кнопка в «Администрирование» → «Система»): учётные записи и ключи, журналы, диалоги, решения эксперта, загруженные документы и папка отдела, справочник, прайс, индекс — архив с контрольными суммами в `backups\`, хранятся 10 последних. В архиве хэши паролей и журналы вопросов — храните его по правилам ИБ. По расписанию: `scripts\install_tasks.bat` регистрирует в Планировщике Windows ежедневную копию и проверку почты, папки отдела и цен 1С; если копии нет больше двух дней или задача завершилась с ошибкой, администратор видит предупреждение. Настройки подключений — `data\settings.env` (образец рядом).
6. Обновление версии — **не поверх старой**: в поставке индекс, справочник и прайс демонстрационные и заменили бы данные заказчика. В старой установке `python scripts\backup.py create`, новая поставка ставится рядом (`install.bat`), в новой — `python scripts\backup.py restore <архив>` (чат и API остановлены; текущее состояние сохраняется страховочной копией), затем `check_demo.py`.

## Подключение данных

- **Документы:** PDF (в том числе сканы — распознавание без интернета), DOCX; пункты и страницы
  определяются автоматически.
- **Учётная база:** любое подключение только для чтения (SQLite в демо; 1С и ERP — через копию или ODBC)
  и описание таблиц понятными словами (`data/demo_db/schema.yaml`, черновик — `scripts/describe_db.py`).
- **Интеграции:** REST API `POST /ask` → ответ, источники (документ, пункт, страница), записи учёта; `POST /tkp` → письмо клиента в черновик ТКП (позиции, цены, Word) без языковой модели.
- **Почта отдела:** IMAP, только чтение (`select … readonly`, `BODY.PEEK` — письма не помечаются прочитанными, ничего не удаляется и не отправляется); сервер, ящик и папка — `KB_MAIL_*`, пароль — `KB_MAIL_PASSWORD` или `data/mail_password.txt` (в git и резервную копию не входит). Для ИБ: агенту нужна учётная запись ящика только на чтение.
- **Цены и остатки из 1С** (`kbagent/onec.py`): стандартный интерфейс OData, только GET-запросы — в 1С ничего не меняется. «Бухгалтерия предприятия 3.0» (`KB_1C_CONFIG=bp`) или УТ 11 / КА 2 / ERP (`KB_1C_CONFIG=ut`); адрес — `KB_1C_URL` (`http://сервер/база/odata/standard.odata`), пользователь — `KB_1C_USER`, пароль — `KB_1C_PASSWORD` или `data/1c_password.txt` (в git и резервную копию не входит), тип цен — `KB_1C_PRICE_TYPE` («Оптовая»), остатки — `KB_1C_STOCK=1`. В 1С: опубликовать базу на веб-сервере с флажком «Публиковать стандартный интерфейс OData»; в «Администрирование» → «Обслуживание» → «Настройка стандартного интерфейса OData» включить справочники «Номенклатура», «Типы цен номенклатуры» (в УТ — «Виды цен»), «Валюты», регистр сведений «Цены номенклатуры»; для остатков — план счетов «Хозрасчетный» и регистр бухгалтерии «Хозрасчетный» (БП, счёт 41.01) или регистр накопления «Товары на складах» (УТ). Для ИБ: отдельный пользователь 1С с правом только на чтение этих объектов. Номенклатура сопоставляется с моделями справочника по артикулу или наименованию; позиция, подходящая к двум моделям, и цена в валюте не загружаются — видно в «Справочник» → «Прайс для ТКП». Обновление — кнопка там же или по расписанию (`scripts\install_tasks.bat`, каждый час).

## Ограничения сейчас

- Скрипты запуска — для Windows; запуск на Astra Linux и РЕД ОС — в работе (код на Python и llama.cpp переносим).
- Учётные записи — свои; вход через Active Directory / ALD Pro — в плане.
- Документы — загрузка в администрировании или папка отдела (`KB_DOCS_FOLDER`, подключается сама по расписанию: `scripts\install_tasks.bat`); подключение систем документооборота — в плане.
